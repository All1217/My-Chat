### 项目名称：My-Chat · 智能对话与知识库系统

**关键词**：Spring Boot 4.1 · Spring AI 2.0 · PostgreSQL pgvector · RAG · Vue 3 · Pinia · Element Plus

**项目简介**：基于大语言模型（DeepSeek V4）的智能对话与知识库问答系统，支持文档上传→向量化→语义检索→AI 流式回答的完整 RAG 链路。

---

### 本轮改动的核心价值

#### 1. RAG 知识库系统（核心功能）

- **知识库 CRUD**：设计并实现知识库与文档元数据的数据库表（`knowledge_base`、`document_meta`），后端 REST API 支持创建/列出/删除/级联清理，前端 Element Plus 侧边栏 + 文档表格展示
- **文档上传与向量化**：上传文档 → 内容解析 → TokenTextSplitter 分片 → pgvector 存储 1536 维 embedding；支持关联到指定知识库（`kbId`），RAG 检索时按 `kbId` 过滤实现知识库隔离
- **向量数据生命周期管理**：删除文档时同步从 pgvector 清理对应 embedding，使用确定性 UUID 算法（`UUID.nameUUIDFromBytes`）实现分片 ID 的可预测重建，确保删除一致性

#### 2. 文档解析引擎扩展

- **多格式支持**：集成 Apache POI 解析 `.docx`/`.xlsx`，集成 jsoup 解析 `.html`，重构为扩展名驱动的调度器（switch-case 模式），新增格式只需加一行
- **文件大小安全限制**：文本文件超过 10MB 自动截断（streaming 读取，不加载全量到内存），Base64 读取上限 50MB

#### 3. 工作区与自定义目录

- **运行时目录切换**：`WorkspaceUtil.switchRoot()` 支持运行时切换工作目录（不写配置文件，仅 JVM 内生效），配套沙箱机制禁止切换到系统关键目录（`C:\Windows`、`/etc` 等）
- **ShellTool 性能优化**：将 AI Tool 从 `ProcessBuilder` fork powershell 进程（每次 ~50MB 内存开销）重写为纯 Java NIO 实现（`ls`/`tree`/`cat`/`grep`/`stat`），零进程开销，路径强制限在 workspace 根目录内
- **目录树懒加载**：前端 el-tree 改为 lazy 模式，后端新增单层按需加载接口（非递归），大目录树不再一次性构建全部节点

#### 4. 系统性能与架构优化

- **虚拟线程**：启用 `spring.threads.virtual.enabled=true`（Java 25 原生支持），Tomcat 线程模型从平台线程切换为虚拟线程，高并发下不再阻塞系统线程池
- **错误修复**：修复对话历史无法自动加载（watch 加 `immediate: true`）、知识库标签显示不同步（改为响应式绑定 `currentChat?.kbId`）、表单无法滚动（CSS flex 布局修复）等多处缺陷

### 技术亮点

| 技术点                                                       | 说明                                                         |
| ------------------------------------------------------------ | ------------------------------------------------------------ |
| Spring AI `VectorStore.similaritySearch` + `filterExpression` | 按 kbId 过滤实现多知识库隔离，无需分库                       |
| `UUID.nameUUIDFromBytes` 确定性 UUID                         | 分片 ID 可由 documentId + index 重建，支持精确删除           |
| Java NIO + DirectoryStream + walkFileTree                    | 替代进程 fork，消除 ShellTool 性能瓶颈                       |
| 路径穿越防护                                                 | `normalize()` + `startsWith(workspaceRoot)`，Spring Framework 同款模式 |
| Pinia 状态管理统一                                           | 将分散在 ChatBox/KnowledgeStore 的 Kb 状态集中到 `chatStore`，消除多源不同步缺陷 |

---

### 可量化成果

- 文档解析格式从 **2 种**扩展到 **6 种**（pdf/docx/xlsx/html/txt/md 等）
- ShellTool 调用从 **50MB + 200ms 进程 fork** 降为 **零额外开销**
- 大目录树加载从 **O(n) 递归全量**变为 **O(1) 按需懒加载**，原先打开大容量、高深度目录页面直接卡死，现在即便打开大型项目也几乎无延迟。
- 修复 **7+** 处前后端缺陷（历史不加载、标签不同步、列表不滚动、重复创建会话等）
