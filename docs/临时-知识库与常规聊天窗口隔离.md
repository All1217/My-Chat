## 分析

你的需求核心是 **常规聊天和知识库聊天完全隔离**，但复用现有组件。让我分析下方案。

### 不需要修改表结构

现有 `chat_sessions` 加一列就够了，但**其实可以不改表**——用 `conversation_id` 前缀或现有 `title` 字段做标记太 hacky。

最干净的方案：**加一列 `kb_id VARCHAR(64) DEFAULT NULL`**，null 表示普通会话，非空表示绑定到某个知识库。

```sql
ALTER TABLE chat_sessions ADD COLUMN kb_id VARCHAR(64) DEFAULT NULL;
```

这样 ChatList 按 `kb_id IS NULL` 或 `kb_id = ?` 过滤，自然分开两套会话列表。

### 架构方案

```
┌─ /chat (普通聊天) ─────────────────────┐
│  ChatView                              │
│  ├─ ChatList → 只显示 kb_id IS NULL    │
│  └─ ChatBox  → 不显示知识库选择器      │
│     └─ streamChat → /ai/normalChat/chat │
└────────────────────────────────────────┘

┌─ /store (知识库聊天) ──────────────────┐
│  KnowledgeStore.vue (现有页面)         │
│  ├─ 左侧: 知识库列表 (已有)             │
│  ├─ 右侧上部: 文档表格 (已有)           │
│  └─ 右侧下部: ChatBox (复用)           │
│     └─ option-bar: 显示已选知识库       │
│     └─ streamChat → /ai/ragChat/chat   │
└────────────────────────────────────────┘
```

### 关键设计决策

**隔离方式**：不新建路由，而是在 `/store` 页面（KnowledgeStore.vue）内，选中一个知识库后，页面下方展示一个 ChatBox 实例。这样：

- 普通聊天在 `/chat` 页面，完全不涉及知识库
- 知识库聊天在 `/store` 页面，只能和选中知识库对话
- 两套 `chat_sessions` 通过 `kb_id` 区分，互不干扰

ChatList 通过传递 `mode` 或 `kbId` prop 来过滤显示哪套会话。

### 数据库

只需一行 ALTER，加在 `schema.sql` 末尾：

```sql
ALTER TABLE chat_sessions ADD COLUMN IF NOT EXISTS kb_id VARCHAR(64) DEFAULT NULL;
```
