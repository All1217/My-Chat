# 大厅新功能接入指引

大厅卡片不是写在页面里的。新功能做成一个「功能包」，在登记表里加一行，大厅就会多一张卡。

现成例子：角色扮演（`my-chat-vue3/src/apps/roleplay/`）。照着抄最快。

---

## 先记住三句话

1. **不要改** `LobbyView.vue`，**不要**把新页面丢进 `src/views/` 根目录。
2. **聊天、知识库、设置、Agent 管道**是骨架，新功能不要往这些包里塞专用代码。
3. 前端路径用 `/app/<功能id>`，后端接口用 `/ai/apps/<功能id>`。一眼能分出「骨架」和「应用」。

---

## 只要一张大厅卡（没有新接口）

以「股市行情」为例，id 用 `market`。

### 第 1 步：建功能包

在 `my-chat-vue3/src/apps/` 下新建目录，至少两个文件：

```text
src/apps/market/
  index.ts                 ← 清单（卡片标题、图标、路由）
  views/MarketView.vue     ← 页面
```

`index.ts` 照角色扮演写，改名字即可：

```ts
import { TrendCharts } from '@element-plus/icons-vue'
import type { AppManifest } from '@/apps/types'

export const marketApp: AppManifest = {
  id: 'market',
  title: '股市行情',
  desc: '查看自选股与盘面摘要',
  icon: TrendCharts,
  color: '#437dff',
  routeName: 'app-market',       // 新功能用 app- 前缀，避免和骨架路由重名
  routePath: '/app/market',
  component: () => import('./views/MarketView.vue'),
  order: 60,                     // 数字越小越靠前；聊天是 10，角色扮演是 20
}
```

页面里放一个「回到大厅」按钮即可：

```ts
router.push({ name: 'lobby' })
```

### 第 2 步：登记（只改这一处骨架文件）

打开 `my-chat-vue3/src/apps/registry.ts`：

1. 顶部 `import { marketApp } from '@/apps/market'`
2. 数组里加上去：

```ts
const registeredApps: AppManifest[] = [...builtinApps, roleplayApp, marketApp]
```

保存后刷新大厅，应该能看到新卡，点进去是 `/app/market`。

**到这里前端入口就完成了。** 路由不用手写，注册表会自动 `addRoute`。

---

## 还要后端接口时

功能包内部仍按「页面 / 接口 / 类型」分层，但整包挂在自己的命名空间下，不要进 `com.mychat.controller`。

### 前端

```text
src/apps/market/
  index.ts
  views/MarketView.vue
  api/index.ts          ← 只打 /ai/apps/market/...
  types.ts              ← 仅本功能用到的类型
```

`api/index.ts` 继续用现有的 `ragClient`：

```ts
import { ragClient } from '@/utils/http'

export const marketApi = {
  quotes: () => ragClient.get<Quote[]>('/ai/apps/market/quotes'),
}
```

### 后端

```text
com.mychat.apps.market/
  MarketController.java          ← @RequestMapping("/ai/apps/market")
  service/
  entity/                        ← 仅本功能的 DTO / PO
  mapper/                        ← 仅本功能需要落库时才建
```

Controller 风格和骨架一样：返回 `Result<T>`，构造器注入 Service。Mapper 接口加 `@Mapper` 即可，启动类已经会扫描 `com.mychat.apps` 下的 Mapper。

共用的东西（`Result`、HTTP 封装、聊天流、Element Plus）继续从骨架引用，不必复制一份。

---

## 要存数据库时

大厅登记表**不上库**，只写在前端代码里。某个功能自己要存数据，再给这个功能加表：

1. 表名带功能前缀，例如 `market_watch`，不要和 `chat_sessions` 抢名字
2. DDL 追加到 `my-chat-server/src/main/resources/schema.sql`（`CREATE TABLE IF NOT EXISTS` + `COMMENT ON`）
3. 对应的 PO、Mapper **只放** `com.mychat.apps.<id>` 包

没有新表就不要建 Controller / Mapper，角色扮演第一期就是这样。

---

## 常用开关

都在该功能的 `index.ts` 清单里改，不用改大厅：

| 想做什么     | 怎么写                    |
| ------------ | ------------------------- |
| 临时下线     | `enabled: false`          |
| 做了页但不出现在大厅 | `showInLobby: false` |
| 调整卡片顺序 | 改 `order`，越小越靠前    |

`enabled: false` 后面厅卡片和路由都会拿掉。

---

## 不要做的事

- 改 `LobbyView.vue` 的卡片列表（那里已经没有列表了）
- 新功能页面放到 `src/views/ChatView.vue` 旁边
- 新 Controller 丢进 `com.mychat.controller`
- 为了「整齐」把聊天 / 知识库搬进 `apps/`（骨架先不动）
- 去改 `router/index.ts` 给新功能加静态路由（设置页带子路由除外，那是骨架）

设置里如果以后要加一个新 Tab，目前仍改 `SettingsView.vue` 的菜单和 `router/index.ts` 的 children，不要塞进大厅注册表。

---

## 对照清单

挂一个新功能前过一遍：

- [ ] `src/apps/<id>/index.ts` 导出了清单
- [ ] 页面在 `src/apps/<id>/views/`
- [ ] `registry.ts` 已 import 并加入数组
- [ ] `id` / `routeName` / `routePath` 三者一致：`foo` → `app-foo` → `/app/foo`
- [ ] 没改 `LobbyView.vue`
- [ ] 有接口则路径是 `/ai/apps/<id>`，类在 `com.mychat.apps.<id>`
- [ ] 有表则表名带功能前缀，DDL 写在 `schema.sql`

做完后打开 `/lobby` 点新卡，再确认旧卡（聊天、设置、知识库、回首页）还能进。
