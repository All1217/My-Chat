# 模拟炒股 · 研究价值等级标准

本文档固化研究卡片字段 `value_tier`（Java/JSON：`valueTier`）的分级阐释与升降级规则。搜集员打标、交易员取票均以此为准；**不**替代账户「投资策略」正文，而是把策略执行拆成可操作的票仓状态机。

数字越小，对当前阶段资本配置的优先级越高。

| 等级 | 含义 | 谁写入 |
|------|------|--------|
| 0 | 已持仓 | 仅系统在 BUY 成交后写入 |
| 1 | 应该买入 | 搜集员（可人工改） |
| 2 | 继续观察 | 搜集员 / SELL 成交后系统回写 |
| 3 | 移出票仓 | 搜集员（`kept=false` 时强制倾向 3） |

与 V8 `source_tier`（信息源层级 A_ONLY / A_PLUS_WEB）无关，勿混淆。

---

## 一、为何这样定标准

行业里常见做法是把观察名单做成**交易就绪漏斗**，而不是一张扁平收藏夹：

- **三层 Watchlist**（可立刻下单 / 成型中 / 雷达）：[SquawkFlow](https://squawkflow.com/learn/building-a-trading-watchlist)、[StockAlarm 周检与「明天会不会买」测试](https://pro.stockalarm.io/blog/weekly-watchlist-review-process)
- **Active vs Monitor**（只差价格或催化剂才买 vs 仍缺研究）：[Swoopr Watchlist Pipeline](https://www.getswoopr.com/research/portfolio-operating-system/watchlist-management/)
- **Core / Active / Bench**：[Tritonix equity research watchlist](https://tritonix.ai/blog/building-watchlist-equity-research-guide)

本项目在漏斗外多一档 **0=已持仓**：持仓是账本状态，不是研究打分。研究侧只评 1/2/3；成交侧负责 0 与卖出后回到 2。

标准制定原则：

1. **对齐当前投资策略**（[`paper-strategy-seed.txt`](../my-chat-server/src/main/resources/paper-strategy-seed.txt) / 账户策略）：低吸企稳、整手与佣金可成交、过滤 ST/流动性/QDII 溢价等。
2. **证据可证伪**：有故事、有风险、有 fit/evidence 分；缺证据不得进 1。
3. **可执行才进买入池**：交易员非持仓候选只吃 `kept=true AND value_tier=1`。
4. **状态机清晰**：BUY→0；SELL→2；已有 0 时搜集员不得覆盖。

## 二、分级详解与 checklist

### 0 · 已持仓

- **含义**：账户当前对该代码有仓位；票仓最高优先级，由交易员管理加减仓与卖出。
- **入选**：仅 `placeOrder` BUY 成功后系统写入。
- **搜集员**：upsert 时若库中已是 0，**保留 0**，可更新 story/风险/分数，但不得改等级。
- **退出**：SELL 全部成交后系统改为 **2**（继续观察），除非人工/下轮搜集判为 3。

### 1 · 应该买入

须同时满足（建议作为搜集员内化 checklist）：

1. `kept=true`，故事与**当前账户策略**一致（相对低点 + 企稳逻辑可被证伪，非「越跌越买」）。
2. `fitScore`、`evidenceScore` 均偏高（建议 **≥ 0.7**；证据分不得低于平台 guardrail 下限）。
3. 入场条件可写清：参考价带 / 企稳形态 / 计划仓位上限；风险（溢价、整手、跳空等）已点名且可接受。
4. 通过策略过滤口径：非 ST、流动性大致够、跨境 ETF 溢价可得且不离谱（细则以策略正文为准）。
5. 非冷却标的；不是「明天才想研究」的半成品。

**自检句**（对齐 StockAlarm）：「若今天收盘后有空仓额度，是否愿意按计划买入？」——明确「是」才标 1。

### 2 · 继续观察

任一成立即可：

- 主题/板块沾边，但证据不足、时机未到，或触发条件距现价仍远。
- fit/evidence 中等，尚不能承诺「明天可买」。
- SELL 后论点未失效，仍值得下轮再评。
- 新建卡片默认档（缺省 `valueTier` 时落库为 2）。

### 3 · 移出票仓

任一成立：

- 论点失效、策略明确排除、或长期无进展。
- `kept=false`（证据不足、池外、拒绝理由成立）——落库强制倾向 **3**。
- 「雷达」长期不晋升且占用注意力的标的，应降到 3 而不是堆在 2。

## 三、升降级规则

| 变更 | 条件 | 执行方 |
|------|------|--------|
| → 1 | checklist 齐、触发临近、「明天会买」为是 | 搜集员 |
| 1 → 2 | 触发远离、证据变差、更好的 1 档挤占额度 | 搜集员 |
| 任意 → 3 | 论点失效 / `kept=false` / 策略排除 | 搜集员 |
| → 0 | BUY 成交成功 | 交易员成交回写 |
| 0 → 2 | SELL 成交成功 | 交易员成交回写 |
| 0 保持 | 搜集员再跑 | upsert 保护，不覆盖 0 |

**与 `kept` 的关系**：

- `kept=false` → 倾向 `value_tier=3`，不进交易员买入池。
- `kept=true` 且 `value_tier=1` → 买入池。
- `kept=true` 且 `value_tier=2` → 仅研究展示，交易员不取。

---

## 四、系统落点（实现摘要）

- 列：`paper_research_note.value_tier`（SMALLINT，默认 2）。
- 搜集员输出契约：`ResearchCardBatch` 含 `valueTier` ∈ {1,2,3}。
- 交易员上下文：非持仓候选 `kept=true AND value_tier=1`；持仓符号始终进上下文。
- BUY 成功 → 0；SELL 成功 → 2。

策略正文变更时，应回看本节 checklist 是否仍匹配；若策略大改，同步修订本文件第「二」节，勿只改 prompt。
