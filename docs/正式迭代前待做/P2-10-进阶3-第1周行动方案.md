## 二、协议细节（本周冻结）

每行一个 JSON，UTF-8，行尾 `\n`：

| type | 必填字段 | 谁发出 |
|------|----------|--------|
| `thinking_delta` | `v,type,turnId,seq,text` | Controller（读 `reasoningContent`） |
| `text_delta` | 同上 | Controller（读 `getText()`） |
| `tool_call` | + `id,name,args` | Advisor |
| `tool_result` | + `id,name,ok,preview,truncated` | Advisor |
| `error` | + `message` | Controller |
| `done` | `v,type,turnId,seq` | Controller（流正常结束） |

常量：

- `v = 1`
- `preview` 最大 **4096** 字符
- `turnId = chatId + "-" + UUID`（或纯 UUID）

示例行：

```json
{"v":1,"type":"tool_call","turnId":"...","seq":1,"id":"call_1","name":"ls","args":{"path":"."}}
{"v":1,"type":"tool_result","turnId":"...","seq":2,"id":"call_1","name":"ls","ok":true,"preview":"...","truncated":false}
{"v":1,"type":"text_delta","turnId":"...","seq":3,"text":"..."}
{"v":1,"type":"done","turnId":"...","seq":4}
```

## 四、核心实现要点

### 4.1 `ObservabilityStreamAdvisor`（对齐官方示例）

```java
// order = Ordered.HIGHEST_PRECEDENCE + 400  // ToolCallingAdvisor 默认约 +300 内侧
// aroundStream: 先扫 request 中未处理过的 ToolResponseMessage → tool_result
//               再 chain.nextStream().doOnNext：若 hasToolCalls → tool_call
// 事件只 tryEmitNext 到请求级 Sinks.Many，绝不改写 ChatClientResponse
```

关键注释（中文）写明：

- **代码路径**：Advisor 旁路 → Controller merge NDJSON
- **工具循环**：仍由自动注册的 `ToolCallingAdvisor` 负责；本类只观测

补充约定：

- `tool_result`：在 `aroundStream` / `aroundCall` **入口**遍历 `request.prompt().getInstructions()`，找 `ToolResponseMessage`，按 tool call id 去重
- `args`：尽量解析为 JSON 对象，失败则 `{"raw":"<string>"}`

### 4.2 `ChatController` 分支

```text
format == null || "plain"
  → produces text/html；现有 textChat / multiModalChat + toThinkingResponse（不动语义）

format == "ndjson"
  → produces application/x-ndjson
  → 创建 Sinks.Many<ChatStreamEvent>
  → 创建 ObservabilityStreamAdvisor(turnId, seqGen, sink)
  → .advisors(obs).advisors(memory param)
  → .stream().chatResponse()
       .doOnNext → thinking_delta / text_delta（仅非空）
       .doOnError → error 事件
       .doOnComplete → done + sink.tryEmitComplete()
  → return Flux.merge(sink.asFlux().map(writer::line), drive.thenMany(empty))
  → doFinally WorkspaceContext.clear()
```

多模态路径同样支持 `format=ndjson`（图片错误时发 `error` 或一条 `text_delta` 提示，与现有 `onErrorResume` 语义对齐）。

### 4.3 与 Memory 的关系（勿踩坑）

- `MessageChatMemoryAdvisor` 保持默认在工具循环**外侧**（现有 `AiConfiguration` 即可）
- 旁路事件**不要**写回主 `Flux` 给 Memory 消费；主链路仍只让 `ToolCallingAdvisor` 过滤后的最终回答出去
- 这与官方删除 `streamToolCallResponses` 的原因一致

## 六、验收用例

```http
POST http://localhost:8100/ai/normalChat/chat?format=ndjson
Content-Type: multipart/form-data

prompt=帮我列出工作区根目录有哪些文件
chatId=obs-week1-test
```

**期望（示意）**：

```json
{"v":1,"type":"tool_call","turnId":"...","seq":1,"id":"...","name":"ls","args":{...}}
{"v":1,"type":"tool_result","turnId":"...","seq":2,"id":"...","name":"ls","ok":true,"preview":"...","truncated":false}
{"v":1,"type":"text_delta","turnId":"...","seq":3,"text":"..."}
{"v":1,"type":"done","turnId":"...","seq":4}
```

**回归**：

```http
POST http://localhost:8100/ai/normalChat/chat
Content-Type: multipart/form-data

prompt=你好
chatId=obs-week1-plain
```

无 `format` → 仍为拼接文本流，前端可正常显示。
