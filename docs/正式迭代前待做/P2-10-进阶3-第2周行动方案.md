## 三、核心设计

### 3.1 类型（`streamEvents.ts`）

```ts
export type ChatStreamEventType =
  | 'thinking_delta' | 'text_delta' | 'tool_call'
  | 'tool_result' | 'error' | 'done'

export interface ChatStreamEvent {
  v: number
  type: ChatStreamEventType
  turnId: string
  seq: number
  text?: string
  id?: string
  name?: string
  args?: unknown
  ok?: boolean
  preview?: string
  truncated?: boolean
  message?: string
}

export type MessagePart =
  | { type: 'thinking'; text: string }
  | { type: 'text'; text: string }
  | {
      type: 'tool'
      id: string
      name: string
      args?: unknown
      status: 'running' | 'done' | 'error' | 'cancelled'
      resultPreview?: string
      ok?: boolean
    }
```

`Message` 扩展：

```ts
export interface Message {
  messageType: string
  text: string
  thinking?: string | null
  parts?: MessagePart[]  // 仅 ASSISTANT；历史消息可无
}
```

### 3.2 `streamChat.ts` 双协议

```ts
// 普通聊天 → NDJSON
const url = kbId
  ? '/rag/ai/ragChat/chat'
  : '/rag/ai/normalChat/chat?format=ndjson'

// 有 kbId：onMessage(chunk) 字符串追加（现状）
// 无 kbId：buffer 按 \n 拆行 → JSON.parse → onEvent(event)
// 不完整末行留在 buffer；流结束 flush
```

回调建议：

```ts
export interface ChatStreamOptions {
  // ...
  onMessage?: (chunk: string) => void      // RAG / 兜底
  onEvent?: (event: ChatStreamEvent) => void // 普通 NDJSON
  onComplete: () => void
  onError: (error: Error) => void
}
```

### 3.3 `useChatStream` 归约规则

| 事件 | 行为 |
|------|------|
| `thinking_delta` | 累加 `streamingThinking` |
| `text_delta` | 累加 `streamingContent` |
| `tool_call` | `streamingParts` 推入 `{type:'tool', status:'running', ...}` |
| `tool_result` | 同 `id` 更新为 `done`/`error`，`resultPreview = unwrap(preview)` |
| `error` | toast 或写入正文前缀；工具 running → `error` |
| `done` | `onComplete` 前把 `parts`+`thinking`+`text` 写入 messages |

`stopStreaming`：所有 `status==='running'` → `'cancelled'`，再按现有逻辑落一条助手消息（含已生成 text + parts）。

历史 `getMessages`：**不改**，仍无 parts（第 3 周）。

### 3.4 `AgentActivityTimeline.vue`

- Props：`parts: MessagePart[]`（过滤 `type==='tool'`）
- `el-timeline` + `el-collapse` 展示 args / result
- running：`el-icon` loading
- 标题：`toolDisplayNames[name] ?? name`
- 样式贴合现有 `.message-ai` Less，不做独立设计体系

### 3.5 `ChatBox.vue` 模板调整（示意）

助手气泡顺序：

1. `AgentActivityTimeline`（有 tool parts 时）
2. thinking `el-collapse`（`msg.thinking` / `streamingThinking`）
3. `MarkdownRenderer`（**仅** `msg.text` / `streamingContent`，不再塞标签）

删除 `parseMessage` 对 `THINKING_START` 的依赖。

### 3.6 工具中文映射（`toolDisplayNames.ts`）

| name | 中文 |
|------|------|
| ls | 列出目录 |
| cat | 读取文件 |
| write | 写入文件 |
| rm | 删除 |
| mv | 移动/重命名 |
| cp | 复制 |
| mkdir | 创建目录 |
| stat | 文件信息 |
| grep | 搜索文本 |
| tree | 目录树 |

未知 MCP（如天气/搜索）：直接显示原始 `name`。

### 3.7 preview 双层引号（前端兜底）

第 1 周实测 `preview` 常为 `"\"目录: ...\""`。`unwrapToolPreview`：

```ts
export function unwrapToolPreview(raw?: string): string {
  if (!raw) return ''
  let s = raw
  try {
    const once = JSON.parse(s)
    if (typeof once === 'string') s = once
  } catch { /* ignore */ }
  return s
}
```
