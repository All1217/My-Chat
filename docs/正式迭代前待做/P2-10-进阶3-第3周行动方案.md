## 一、目标与非目标

### 1.1 目标

1. PostgreSQL 增加 `chat_assistant_turns`（改 [`schema.sql`](../../my-chat-server/src/main/resources/schema.sql) PostgreSQL 段）。
2. 普通聊天 `format=ndjson` 回合结束时，将本轮 **最终态** `parts` / `thinking` / 对齐用 `assistant_text` **异步写入一行**（不落 token 级 `text_delta`）。
3. 历史接口返回 `ChatMessageVO`（含 `parts` / `thinking`），刷新后时间线可回放。
4. 删除会话时同步删除该会话下全部回合行（逻辑外键 `conversation_id` → `chat_sessions`）。
5. 前端 `getMessages` 直接使用后端 `parts`。

### 1.2 非目标

| 不做 | 原因 |
|------|------|
| 改 `spring_ai_chat_memory` 列 | JDBC Memory 为框架契约；官方也不存 tool 消息 |
| `chat_turn_events` 事件流水 | 本周改为「一轮一行 parts」，读路径更贴 UI |
| 迁 Spring AI Session / OTEL | 运维与改动面过大，留给后续 |
| RAG `retrieval` / Agent route UI | 本周收窄范围 |
| 超大结果二次拉取全文 | 沿用 4KB `preview` + `truncated` |

## 二、关键设计决策（已锁定）

### 2.1 存储模型：一轮一行 + `parts` JSONB

| 写入（每轮最多 1 行） | 不写入 |
|------------------------|--------|
| 归约后的 `parts`（`ToolMessagePart[]`） | 逐 token `text_delta` / 逐条 `tool_*` 事件行 |
| `thinking`（可空） | `done` 事件本身 |
| `assistant_text`（拼接正文，供对齐/校验） | 会话级大 JSON 塞进 `chat_sessions` |
| `assistant_ordinal`（会话内第几个 ASSISTANT，0-based） | `memory_sequence_id`（本周不做回填竞态） |

无工具且无 thinking 的闲聊回合：**可不写行**（或写空 `parts='[]'`，实现时统一「有 tool/thinking 才 insert」以省空间）。

### 2.2 与助手消息对齐（不改 Memory 表）

当前 `getMessages` 返回 Spring AI `Message`，无法挂 `parts`。

**改为**返回 `List<ChatMessageVO>`：

1. `chatMemory.get(conversationId)` → VO（`messageType` + `text`）。
2. 查 `chat_assistant_turns`，按 `assistant_ordinal` 升序。
3. **主对齐**：对 Memory 中第 `i` 个 ASSISTANT（0-based），若存在 `assistant_ordinal = i` 的回合行，挂上其 `parts` / `thinking`。
4. **兜底**：若 ordinal 缺失或错位，用 `assistant_text` 与 ASSISTANT.`text` **精确匹配**；仍失败则跳过（该气泡无时间线，不串轮硬绑）。

写入时 `assistant_ordinal` 取值：流结束异步落库前，读取 `chatMemory.get(conversationId)` 中 ASSISTANT 条数，取 **`count - 1`**（本轮刚写入的那条）。若 Memory 尚未可见（竞态），延迟极短重试一次或仅写 `assistant_text` 靠兜底匹配（日志告警）。

### 2.3 写入时机

在 `ChatController` 回合内：

- 与 Sink 并行累积 `ChatStreamEvent`（或直接维护与前端同构的 parts 归约状态）。
- `ON_COMPLETE` / `doFinally`：先保证客户端收到 `done`，再  
  `Mono.fromRunnable(save).subscribeOn(Schedulers.boundedElastic()).subscribe()`，**禁止阻塞**序列化线程。
- `ON_ERROR` / cancel：若已有 tool parts，同样尽量落库（`assistant_text` 可为不完整正文）。

### 2.4 删除级联

删除 `chat_sessions` 时调用 `ChatAssistantTurnService.deleteByConversation(conversationId)`。  
库表层用逻辑外键即可（应用级联）；可选加注释说明关联，**不强制** DB `REFERENCES`（与现网 Memory 风格一致）。

## 三、数据库（必须改 schema.sql）

在 **PostgreSQL 段**追加（替代技术方案原文中的 `chat_turn_events` 作为本周落地形态）：

```sql
-- 助手回合 UI 轨迹（进阶 3：工具时间线回放）
-- 逻辑外键 conversation_id → chat_sessions.conversation_id
-- 不修改 spring_ai_chat_memory
CREATE TABLE IF NOT EXISTS chat_assistant_turns (
  id                 BIGSERIAL PRIMARY KEY,
  conversation_id    VARCHAR(255) NOT NULL,
  turn_id            VARCHAR(128) NOT NULL,
  assistant_ordinal  INT          NOT NULL,
  assistant_text     TEXT,
  thinking           TEXT,
  parts              JSONB        NOT NULL DEFAULT '[]'::jsonb,
  created_at         TIMESTAMP    DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT uq_assistant_turn UNIQUE (conversation_id, turn_id),
  CONSTRAINT uq_assistant_ordinal UNIQUE (conversation_id, assistant_ordinal)
);

CREATE INDEX IF NOT EXISTS idx_assistant_turns_conv
  ON chat_assistant_turns (conversation_id, assistant_ordinal);

COMMENT ON TABLE chat_assistant_turns IS '每轮 ASSISTANT 的 UI parts/thinking，用于刷新后时间线回放';
COMMENT ON COLUMN chat_assistant_turns.conversation_id IS '逻辑外键，对应 chat_sessions.conversation_id';
COMMENT ON COLUMN chat_assistant_turns.turn_id IS '与流式 NDJSON 的 turnId 一致';
COMMENT ON COLUMN chat_assistant_turns.assistant_ordinal IS '该会话内 ASSISTANT 消息序号（0-based），用于与 Memory 对齐';
COMMENT ON COLUMN chat_assistant_turns.parts IS '归约后的 MessagePart[] JSON，与前端 ToolMessagePart 同构';
```

**运维注意**：本地已有库需**手动执行**同等 DDL（无 Flyway 时 `schema.sql` 仅作新环境参考）。

若曾按旧方案建过 `chat_turn_events`，本周以 `chat_assistant_turns` 为准，旧表可废弃不迁（尚无生产数据）。

## 五、接口与数据结构

### 5.1 历史接口（返回形态变更）

```http
GET /ai/history/getMessages/{conversationId}
```

成功时 `Result.data` 示例：

```json
[
  { "messageType": "USER", "text": "列出工作区文件" },
  {
    "messageType": "ASSISTANT",
    "text": "工作区根目录下有……",
    "thinking": null,
    "parts": [
      {
        "type": "tool",
        "id": "call_xxx",
        "name": "ls",
        "args": { "path": "." },
        "status": "done",
        "ok": true,
        "resultPreview": "目录: . ……",
        "truncated": false
      }
    ]
  }
]
```

`messageType` 统一为大写：`USER` / `ASSISTANT` / …（与现网前端一致）。

### 5.2 `parts` JSON 约定

与前端 [`streamEvents.ts`](../../my-chat-vue3/src/types/AiModule/streamEvents.ts) 中 `ToolMessagePart` 同构；落库前完成：

1. `tool_call` → 创建/更新 part（`status: running`）
2. 同 `id` 的 `tool_result` → `done`/`error` + `resultPreview`（unwrap 双层 JSON 引号）
3. 流中断未完成 → `cancelled`（与第 2 周前端一致）
4. **不**把最终回答正文再塞进 `parts`（正文仍在 Memory / VO.`text`）

### 5.3 `saveTurn` 伪代码

```java
void saveTurn(String conversationId, String turnId, List<ChatStreamEvent> events) {
    TurnSnapshot snap = TurnPartsReducer.reduce(events); // parts, thinking, assistantText
    if (snap.parts().isEmpty() && isBlank(snap.thinking())) {
        return; // 闲聊无轨迹，跳过
    }
    int ordinal = resolveAssistantOrdinal(conversationId); // memory ASSISTANT count - 1
    ChatAssistantTurn row = new ChatAssistantTurn();
    row.setConversationId(conversationId);
    row.setTurnId(turnId);
    row.setAssistantOrdinal(ordinal);
    row.setAssistantText(snap.assistantText());
    row.setThinking(snap.thinking());
    row.setParts(toJson(snap.parts()));
    // insert；唯一键冲突则 update；失败只打日志
}
```

## 八、风险与缓解

| 风险 | 缓解 |
|------|------|
| Memory 落库晚于异步 save，ordinal 偏小 | 短延迟重试一次；失败则依赖 `assistant_text` 兜底 |
| 唯一键 `(conversation_id, assistant_ordinal)` 冲突 | upsert 或跳过并打 warn |
| 异步写库失败 | error 日志，不影响已结束的 HTTP 流 |
| `getMessages` 返回类型变更 | 前端 `Message` 已含可选 `parts` |
| 旧会话无回合行 | `parts` 为空，时间线不渲染 |

## 十、与技术方案原文的差异说明

技术方案 §六 曾示例 `chat_turn_events`（事件流水）。本周落地改为 **`chat_assistant_turns`（一轮一行 parts）**，原因：

- 更贴产品 UI「消息 + content parts」模型，读路径无需再聚合  
- 仍用本地建表 + 逻辑外键关联 `chat_sessions`，不碰框架 Memory  
- 事件级审计 / Session / Langfuse 不在本周范围  

后续若需要完整 event log 或迁 Spring AI Session，可另开迭代，与本表并存或迁移。
