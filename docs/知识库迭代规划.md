## 知识库管理功能建议清单

### 现有基础（已具备）

| 模块                                               | 状态   |
| -------------------------------------------------- | ------ |
| 文件上传→解析（PDF/文本）→分片→向量化存入 pgvector | 已实现 |
| 工作区文件浏览（树+表格+预览+右键菜单）            | 已实现 |
| Spring AI ChatClient + 流式 SSE 输出               | 已实现 |
| Element Plus + Pinia 前端框架                      | 已实现 |

---

### 一、建议新增功能清单（按优先级排列）

#### 🔴 P0 — 核心骨架（缺了无法使用）

| #    | 功能                           | 说明                                                         |
| ---- | ------------------------------ | ------------------------------------------------------------ |
| 1    | **知识库 CRUD（后端 + 前端）** | 创建/列出/删除知识库，每个知识库是独立的文档集合             |
| 2    | **文档元数据表 + 列表页**      | 记录每篇文档的文件名、大小、分片数、状态（PROCESSING/READY/FAILED）、上传时间、所属知识库；前端表格展示 |
| 3    | **上传文档→指定知识库**        | 当前 upload 没有 `kbId` 参数，无法归入特定知识库             |
| 4    | **删除文档（同步清理向量）**   | 目前只存不删，需从 pgvector 移除对应 Document 的 embedding   |
| 5    | **知识库级联删除**             | 删除知识库时一并删掉其所有文档 + 向量                        |
| 6    | **RAG 检索接口**               | 接收 query + kbId → `VectorStore.similaritySearch` → 拼接上下文 → ChatClient 流式回答 |

#### 🟡 P1 — 可用性提升

| #    | 功能                        | 说明                                                         |
| ---- | --------------------------- | ------------------------------------------------------------ |
| 7    | **批量上传文档**            | 支持一次选多个文件，并行/串行上传到同一知识库                |
| 8    | **批量删除 + 批量重新索引** | 表格多选后一键操作                                           |
| 9    | **分片查看**                | 在 UI 上查看某篇文档被切成了哪些文本片段，辅助调试 chunkSize |
| 10   | **检索测试区**              | 输入问题，展示命中的片段（含相似度分数）+ 模型最终回答，帮助调优 |
| 11   | **更多文档格式支持**        | 当前只支持 PDF 和纯文本；建议增加 **docx（Apache POI）**、**HTML（jsoup）**、**Markdown**（已有部分支持） |
| 12   | **文档状态反馈**            | 上传后轮询或 SSE 推送处理进度（PROCESSING → READY），当前是同步阻塞，大文件会超时 |

#### 🟢 P2 — 体验增强

| #    | 功能                 | 说明                                                         |
| ---- | -------------------- | ------------------------------------------------------------ |
| 13   | **分片参数可配置**   | 知识库级别自定义 chunkSize / chunkOverlap / topK，调参无需改代码 |
| 14   | **文档标签/分类**    | 给文档打标签 el-tag，支持按标签筛选                          |
| 15   | **知识库统计仪表盘** | 文档数、分片数、预估 token 用量、向量占用空间                |
| 16   | **重新向量化**       | 已上传文档的"重新索引"按钮，适用于修改分片参数后刷新         |
| 17   | **嵌入模型可切换**   | 当前 embedding model 在 application.yaml 硬编码 `text-embedding-v4`，做成可选的 |
| 18   | **Web 爬虫导入**     | 输入 URL 自动抓取页面内容并向量化（路线图中的"全自动网络数据采集"） |

### 二、建议实施顺序

```
第一轮（P0，缺了不能上线）
  1.1  建表：knowledge_base + document_meta
  1.2  后端：知识库 CRUD API + 上传归入 kb + 删除（含向量清理）
  1.3  后端：RAG 查询接口（similaritySearch + ChatClient）
  1.4  前端：知识库列表（侧边栏） + 文档表格 + 上传/删除 + 检索测试区
  → 此时知识库功能可独立使用

第二轮（P1，优化日常使用）
  2.1  批量操作（上传/删除/重新索引）
  2.2  分片查看对话框
  2.3  更多文档格式解析器
  2.4  异步处理 + 状态反馈

第三轮（P2，按需迭代）
  3.1  分片参数配置界面
  3.2  标签/分类系统
  3.3  统计仪表盘
  3.4  嵌入模型切换
  3.5  Web 爬虫导入
```

### 三、值得调研的成熟产品

| 产品                                                         | 推荐理由                                             | 关注点                                                       |
| ------------------------------------------------------------ | ---------------------------------------------------- | ------------------------------------------------------------ |
| **[Dify](https://github.com/langgenius/dify)（开源）**       | 知识库 → 检索 → 对话的完整链路，UI/UX 参考价值极高   | 文档列表布局、检索测试页、分块参数配置界面                   |
| **[FastGPT](https://github.com/labring/FastGPT)（开源）**    | 同样是知识库+RAG，流程可视化编排                     | 知识库管理的交互设计、批量导入流程、向量检索调试             |
| **[MaxKB](https://github.com/1Panel-dev/MaxKB)（开源）**     | 轻量级知识库问答系统，后端 Java 技术栈，与你项目接近 | 知识库 → 文档 → 分段的三级结构、权限模型                     |
| **[AnythingLLM](https://github.com/Mintplex-Labs/anything-llm)（开源）** | 多模型/多向量库支持，工作区概念类似知识库            | 工作区隔离设计、文档拖拽上传体验                             |
| **LangSmith / LangFuse（开源）**                             | LLM 可观测性平台                                     | **仅参考其 Trace 和检索评估思路**，不直接用于知识库          |
| **腾讯云知识引擎 / 阿里云百炼**                              | 商业产品，功能全面                                   | 文档预处理流程（自动识别版式/去噪/分段策略），**适合找灵感但不要照搬复杂功能** |

> 建议重点看 **Dify** 和 **FastGPT** 的文档管理页面、检索测试页面的交互设计，这两个最贴近你的项目场景。
