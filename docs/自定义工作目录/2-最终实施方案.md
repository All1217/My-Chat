## 行动方案：会话级工作目录隔离

### 架构概要

```
前端发起请求 (携带 chatId)
    ↓
Controller 方法体 → 查 DB 获取该会话的 workDir
    ↓
WorkspaceContext.set(workDir)   ← ThreadLocal
    ↓
ShellTool.resolveSafe() → WorkspaceContext.get() → 正确的工作目录
    ↓
请求结束 → WorkspaceContext.clear()
```

**不依赖拦截器/过滤器**，直接在 Controller 方法体内显式设置 ThreadLocal，避免 FormData 参数解析时序问题。

#### 1. 新建 `WorkspaceContext.java` — ThreadLocal 持有者

`my-chat-server/src/main/java/com/mychat/config/WorkspaceContext.java`

```java
package com.mychat.config;

/**
 * 线程级工作目录上下文持有者。
 * 每个 HTTP 请求线程独立，解决 WorkspaceUtil 全局单例的并发问题。
 */
public class WorkspaceContext {
    private static final ThreadLocal<String> WORK_DIR = new ThreadLocal<>();

    public static void set(String workDir) {
        WORK_DIR.set(workDir);
    }

    public static String get() {
        return WORK_DIR.get();
    }

    public static void clear() {
        WORK_DIR.remove();
    }
}
```

#### 2. 修改 `WorkspaceUtil.java` — 从 ThreadLocal 读取工作目录

**变更点：**
- `resolveSafe()` 优先从 `WorkspaceContext.get()` 获取根目录，fallback 到默认 `workspaceRoot`
- `switchRoot()` 改为设置 ThreadLocal（一次请求有效），而非修改全局字段
- 保留 `workspaceRoot` 字段作为默认值，供无会话上下文的请求使用

```java
// resolveSafe() 改为：
public Path resolveSafe(String relativePath) {
    String currentRoot = WorkspaceContext.get();
    Path root = (currentRoot != null) ? Paths.get(currentRoot).toAbsolutePath().normalize() : workspaceRoot;
    // ... 其余逻辑不变
}

// switchRoot() 改为：
public String switchRoot(String newPath) {
    Path resolved = Paths.get(newPath).toAbsolutePath().normalize();
    // ... 校验逻辑不变 ...
    WorkspaceContext.set(resolved.toString());  // 只设 ThreadLocal，不污染全局
    log.info("工作目录(ThreadLocal)已切换至: {}", resolved);
    return resolved.toString();
}
```
