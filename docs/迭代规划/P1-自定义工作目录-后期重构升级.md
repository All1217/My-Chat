## 日志分析

从最新日志看，ShellTool 面临一系列连锁问题。以下是逐层分析：

### 问题 1（根因）：空格即参数分隔符 — 导致所有多词路径操作出错

这是**最致命**的设计缺陷。ShellTool 的所有命令都用 `split("\\s+")` 解析参数，而中文文件名经常包含空格：

| 用户输入                          | 工具实际解析                                   | 结果                                     |
| --------------------------------- | ---------------------------------------------- | ---------------------------------------- |
| `rm 我的文件夹 测试文本文件.txt`  | `rm 我的文件夹` + `rm 测试文本文件.txt`        | 文件夹被删，文件报错                     |
| `mv a.txt b.txt 我的文件夹/`      | `mv a.txt` → `b.txt 我的文件夹/`（重命名合并） | a.txt → "b.txt 我的文件夹/" 的奇怪文件名 |
| `cat 我的文件夹 测试文本文件.txt` | `cat 我的文件夹` → 空目录                      | 误读                                     |

### 问题 2：AI 持续尝试 Unix shell 语法（因为 @Tool 的描述像 shell）

| 模型尝试                       | 原因                 | 错误                               |
| ------------------------------ | -------------------- | ---------------------------------- |
| `ls -la`, `ls -1`              | 误以为有 flags       | 已修复，但 flag 被忽略后结果无差异 |
| `dir /b`                       | 尝试 Windows cmd     | 路径 `/b` 不存在                   |
| `rm *.txt`                     | shell 通配符         | `*` 是非法字符                     |
| `ls \| cat`                    | shell pipe           | `\|` 是非法字符                    |
| `python -c "..."`              | 放弃工具，尝试子进程 | 不支持                             |
| `rm "测试.txt"`                | 引号转义             | `"` 是非法字符                     |
| `mv "带空格的文件.txt" target` | shell 引号           | `"` 是非法字符                     |

### 问题 3：`write` 不支持 `\n` 换行符

AI 在 JSON 中生成 `\\n`（字面反斜杠 n），`write` 直接写入文件字符而非换行。

### 问题 4：`mv` 只支持单源→单目标，不支持多源→目录

模型的标准操作 `mv a.txt b.txt 我的文件夹/` 本意是移动多个文件到目录，但工具将其理解为 `重命名 a.txt → "b.txt 我的文件夹/"`。

## 重构方案

### 第一阶段（高优先级）：修复根因 — 空格文件名支持

**核心思路**：引入类 shell 的参数解析，保留以下语法：

- `rm 我的文件夹 测试文本文件.txt` → 仍按空格拆分（无好的办法），但 **`rm` 失败时不删除已有路径**
- 更重要的：提供**备选操作**让 AI 通过 `write` 和 `cat` 绕过空格问题

但实际上，从 Cursor 的做法看，更先进的方案是**拆分为多个独立 @Tool 方法**，每个工具接收明确的参数，而非一个 `executeCommand` 解析字符串。

**建议重构方案：拆分为独立工具方法**

```java
@Tool(description = "读取文件内容")
public String readFile(@ToolParam(description = "文件路径") String path) { ... }

@Tool(description = "写入文件内容（覆盖）")
public String writeFile(
    @ToolParam(description = "文件路径") String path,
    @ToolParam(description = "写入内容") String content) { ... }

@Tool(description = "删除文件或目录")
public String delete(
    @ToolParam(description = "要删除的路径") String path) { ... }

@Tool(description = "列出目录内容")
public String listDirectory(
    @ToolParam(description = "目录路径，默认当前目录") String path) { ... }

@Tool(description = "移动/重命名文件或目录")
public String move(
    @ToolParam(description = "源路径") String source,
    @ToolParam(description = "目标路径") String target) { ... }

@Tool(description = "复制文件或目录")
public String copy(
    @ToolParam(description = "源路径") String source,
    @ToolParam(description = "目标路径") String target) { ... }

@Tool(description = "创建目录")
public String createDirectory(
    @ToolParam(description = "目录路径") String path) { ... }

@Tool(description = "在文件中搜索文本")
public String grep(
    @ToolParam(description = "搜索模式") String pattern,
    @ToolParam(description = "搜索路径，默认当前目录") String path) { ... }
```

**优势**：
- 每个参数由 Spring AI 框架编码为 JSON，空格是 JSON 字符串的一部分，不会被拆分
- AI 模型容易理解：`readFile(path: "我的文件夹/测试.txt")` 而非 `cat 我的文件夹/测试.txt`
- 框架支持 `@ToolParam` 描述，模型能理解每个参数含义
- 不再需要手动解析 `\n` 换行 — Spring AI 框架在 JSON 反序列化时自动处理

### 第二阶段（中优先级）：增强工具稳定性

1. **`write` 检测换行符**：将 `\\n`、`\n`、`\\r\\n` 等统一转换为实际换行
2. **`mv` 支持多源→目录**：追加参数以支持 `move(source1, target)` 和 `move(source1, source2, target)` 重载
3. **`ls` 显示文件类型**：区分文件/目录显示更清晰，避免 `ls -la` 的需求
4. **`Stat` 返回更详细信息**：文件大小、修改时间、类型

### 第三阶段（低优先级）：高级功能

1. **glob 匹配**：支持 `*.txt` 在 `delete`/`grep` 中
2. **文件搜索**：递归搜索匹配模式的文件名
3. **差异比较**：两个文件内容比较
4. **文件预览**：对超大文件只返回前 N 行

---

## 需要注意的设计决策

1. **是否保持单一 `executeCommand` 方法** — 简单但有很多 shell 语法陷阱。拆分是最彻底的方案。
2. **安全边界**：`WorkspaceUtil.resolveSafe()` 已经限制了路径穿越，但多工具方法中每条路径都需要检查。
3. **AI 模型选择**：deepseek-v4-flash 对复杂工具调用的可靠性有限，改用更强大的模型（如 deepseek-v4-pro）能显著减少幻觉问题。

## 核心差异分析

### 当前实现（一个问题）

```java
@Tool(description = "在工作目录中执行文件操作。" +
        "可用操作: ls, tree, cat, grep, stat, write, mkdir, rm, mv, cp。" +
        "示例: 'rm old.txt', 'mv a.txt b.txt', 'cp src.txt dst.txt'")
public String executeCommand(
        @ToolParam(description = "操作命令，格式: <操作> [参数...]") String command) {
    // 内部按空格 split("\\s+") 解析
    // 所有解析错误都导致操作失败
}
```

**瓶颈**：全部 10 个操作挤在一个 `String command` 参数里，AI 模型看到的只是一个黑盒字符串，它必须自己模拟 shell 语法（引号、转义、通配符、管道），而这些 ShellTool 全都不支持。

### 官方推荐做法（多方法）

```java
// 每个操作是独立的 @Tool，参数由 JSON Schema 描述，模型自然理解
class FileTools {
    @Tool(description = "读取文件内容")
    String readFile(@ToolParam(description = "文件路径") String path) { ... }

    @Tool(description = "写入内容到文件（覆盖）")
    String writeFile(
        @ToolParam(description = "文件路径") String path,
        @ToolParam(description = "写入的内容") String content) { ... }

    @Tool(description = "删除文件或目录")
    String delete(@ToolParam(description = "要删除的路径") String path) { ... }

    @Tool(description = "列出目录内容")
    String listDirectory(
        @ToolParam(description = "目录路径，默认当前目录") String path) { ... }
}
```

## 可获得的具体改进

### 1. 参数不再需要字符串解析（最核心）

**当前**：AI 生成 `"command": "write 测试.txt 这是一句测试"` → ShellTool 手动 split 空格 → 遇到中文空格直接出错

**官方做法**：AI 生成 `{"path": "测试.txt", "content": "这是一句测试"}` → Spring AI 框架自动用 Jackson 反序列化 → `writeFile(path, content)` 直接收到正确的参数

✅ 空格文件名、中文路径、含空格的正文内容，全部自然支持

### 2. 模型更容易理解和调用

**当前**：`@Tool description` 里写了 10 个操作和所有示例，模型需要用"阅读理解"的方式记住

**官方做法**：每个操作独立 `@Tool(description = "...")`，模型只需要决定"我要读文件 → 调用 readFile"，参数 Schema 由框架自动生成并告诉模型

✅ 减少模型在"选工具 + 选操作"两个维度的决策负担

### 3. 利用 `@ToolParam(required = false)` 实现可选参数

```java
@Tool(description = "列出目录内容")
String listDirectory(
    @ToolParam(description = "目录路径，默认为当前目录", required = false) String path) { ... }
```

✅ 模型可以不传 path 参数，自动使用当前目录

### 4. `returnDirect` 支持

`@Tool(returnDirect = true)` 可以让工具结果直接返回给客户端而不是返回给模型。这对 AI 不需要继续处理的场景（如读取文件内容给用户看）非常有用。

### 5. 工具自动注册到 ChatClient

```java
@Bean
ToolCallback currentWeather() { ... }
```

Spring 自动发现 `@Bean ToolCallback`，`AiConfiguration` 中通过 `toolChatClient.prompt().tools(...)` 或 `defaultTools(...)` 按需使用。

## 解决的问题清单

| 当前问题                          | 拆分后的解决方式                               |
| --------------------------------- | ---------------------------------------------- |
| 空格文件名被 split 拆开           | 参数为独立 JSON 字段，Spring AI 框架处理       |
| `\n` 换行符被吞                   | `content` 为完整 JSON string，换行符由框架处理 |
| 模型用 `ls -la` 等 flags          | `ls()` 不接收 flags，模型自然学会只传路径      |
| 模型用 `*` 通配符                 | 不存在的操作，模型不会尝试                     |
| 模型用 `"` 引号转义               | 不需要转义，JSON 参数天然支持空格              |
| 模型用 `\|` pipe                  | 不存在 pipe 操作，模型不会尝试                 |
| `mv a.txt b.txt 文件夹/` 语义歧义 | `mv(source, target)` 明确的两个参数            |
| 长对话中模型忘记工具的细节        | 每个操作独立命名 + 独立 description，意图清晰  |
| `python -c` 等子进程尝试          | 不可用的操作名称在工具列表中不存在             |
