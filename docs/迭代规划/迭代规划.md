# 建议新增功能清单

### 🔴 P0 — 核心骨架（全部已办结）

| 功能                                                  | 说明                                                         |
| ----------------------------------------------------- | ------------------------------------------------------------ |
| **知识库 CRUD（后端 + 前端）**                        | 创建/列出/删除知识库，每个知识库是独立的文档集合             |
| **文档元数据表 + 列表页**                             | 记录每篇文档的文件名、大小、分片数、状态（PROCESSING/READY/FAILED）、上传时间、所属知识库；前端表格展示 |
| **上传文档→指定知识库**                               | 当前 upload 没有 `kbId` 参数，无法归入特定知识库             |
| **删除文档（同步清理向量）**                          | 目前只存不删，需从 pgvector 移除对应 Document 的 embedding   |
| **知识库级联删除**                                    | 删除知识库时一并删掉其所有文档 + 向量                        |
| **RAG 检索接口**                                      | 接收 query + kbId → `VectorStore.similaritySearch` → 拼接上下文 → ChatClient 流式回答 |
| **利用 Spring AI 的 metadata 过滤机制实现知识库隔离** |                                                              |

### 🟡 P1 — 可用性提升

| 功能                   | 说明                                                         | 进度     |
| ---------------------- | ------------------------------------------------------------ | -------- |
| **批量上传文档**       | 支持一次选多个文件，并行/串行上传到同一知识库                | 初步实现 |
| **更多文档格式支持**   | 当前只支持 PDF 和纯文本；建议增加 **docx（Apache POI）**、**HTML（jsoup）**、**Markdown**（已有部分支持） | 初步实现 |
| **实现自定义工作目录** | 效仿opencode，前端增设“打开项目”按钮，点击后输入磁盘目录可切换过去，AI可自由针对该目录下文件进行增删改查 | 初步实现 |
| **区分AI工作模式**     | 区分plan、build、debug、chat四种工作模式，每种模式有专用的系统提示词（需要先了解不同提示词优先级） |          |
| **会话支持上传文档**   |                                                              | 初步实现 |

### 🟢 P2 — 体验增强

| 功能                                     | 说明                                                         | 进度     |
| ---------------------------------------- | ------------------------------------------------------------ | -------- |
| **分片参数可视化配置**                   | 知识库级别自定义 chunkSize / chunkOverlap / topK，调参无需改代码 | 初步实现 |
| 召回测试                                 |                                                              | 初步实现 |
| **知识库统计仪表盘**                     | 文档数、分片数、预估 token 用量、向量占用空间                |          |
| **重新向量化**                           | 已上传文档的"重新索引"按钮，适用于修改分片参数后刷新         | 初步实现 |
| **模型可切换**                       |  | 初步实现 |
| **全面升级前端聊天交互渲染** | 结构化输出和时间线                                           | 初步实现 |
| global query能力缺失                     | 让AI总结知识库，它直接拿这句话搜相关文档，但是搜出来的结果相关性太低，全部被过滤，AI误以为无结果，回答“找不到相关信息” |初步实现|
| **接入MCP协议**              | 详见`./P2-9-mcp协议规划.md`、`./P2-9-接入第三方MCP服务行动方案.md` | 初步实现 |
| **agents开发**               | 详见`./P2-10-agents开发规划.md`                              | 初步实现 |
| 异步任务 + 消息通知机制                  |                                                              | 初步实现 |
| 父子分段                                 | 切段有两层：子块小，用来检索（命中准） 父块大，命中后把整段上下文送给模型（回答不碎）。Dify 的父子分段：关键词打在子块上，预览里还能看到所属父段。代价：入库结构更复杂，要记父子关系；和「总览全库」仍无关，只改善单点问答的完整度。 |          |
| Rerank                                   | 向量检索先粗召回几十条（又快又便宜，但排序比较糙），再用一个专门的重排模型给「问题和片段」打分，只把前几条送给 LLM。像先用渔网捞一桶，再用细筛挑最相关的几条。Dify / FastGPT 可选手动开。代价：多一次模型调用，贵、慢；你们现在 topK=5 时收益有限。 |          |
| 混合检索                                 | 向量检索只看语义像不像（「封装」能搜到「把细节藏起来」）。全文检索只看字面（「equals」「TCP 三次握手」这种专有名词很稳）。混合是两路都搜，再用 RRF 之类把名单合成一份。FastGPT 知识库搜索配置里的「语义 / 全文 / 混合」就是这个。适合：编号、报错码、API 名和自然语言混在一起。代价：要有全文索引（不止 pgvector），实现和调参都更重。 |          |
| 知识库聊天引用（来源文件名） |  | 初步实现 |
| **按文档看分段（只读即可）** |  | 初步实现 |

# 值得调研的成熟产品

| 产品                                                         | 推荐理由                                             | 关注点                                                       |
| ------------------------------------------------------------ | ---------------------------------------------------- | ------------------------------------------------------------ |
| **[Dify](https://github.com/langgenius/dify)（开源）**       | 知识库 → 检索 → 对话的完整链路，UI/UX 参考价值极高   | 文档列表布局、检索测试页、分块参数配置界面                   |
| **[FastGPT](https://github.com/labring/FastGPT)（开源）**    | 同样是知识库+RAG，流程可视化编排                     | 知识库管理的交互设计、批量导入流程、向量检索调试             |
| **[MaxKB](https://github.com/1Panel-dev/MaxKB)（开源）**     | 轻量级知识库问答系统，后端 Java 技术栈，与你项目接近 | 知识库 → 文档 → 分段的三级结构、权限模型                     |
| **[AnythingLLM](https://github.com/Mintplex-Labs/anything-llm)（开源）** | 多模型/多向量库支持，工作区概念类似知识库            | 工作区隔离设计、文档拖拽上传体验                             |
| **LangSmith / LangFuse（开源）**                             | LLM 可观测性平台                                     | **仅参考其 Trace 和检索评估思路**，不直接用于知识库          |
| **腾讯云知识引擎 / 阿里云百炼**                              | 商业产品，功能全面                                   | 文档预处理流程（自动识别版式/去噪/分段策略），**适合找灵感但不要照搬复杂功能** |

> 建议重点看 **Dify** 和 **FastGPT** 的文档管理页面、检索测试页面的交互设计，这两个最贴近你的项目场景。
