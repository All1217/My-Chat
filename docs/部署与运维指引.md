# 部署与运维指引（阿里云 CentOS 7.9）

样例：[`deploy/`](../deploy/)。复用宿主机 **`pg`**（pgvector:pg18，`/data/pgdata`）；Compose 只跑 **app + nginx**；Jenkins / Dozzle / Adminer 为可选 compose profile（不 yum 安装）。

业务站：`http://<公网IP>/`。Jenkins / 日志 / 查库：仅本机端口，用 SSH 隧道访问（见第 4 节）。

本文合并：**首次部署、日常发布、Jenkins、容器日志（Dozzle）、数据库可视化（Adminer）**。

---

## 1. 服务器配置现状与建议

| 项 | 现状 / 建议 |
|----|-------------|
| 规格 | 2C4G；**Swap ≥2GB**（必做） |
| Docker | Compose v2；国内建议配 `registry-mirrors`（阿里云加速器 / DaoCloud），`daemon.json` 必须是合法 JSON |
| 已有 `pg` | **复用**；为本项目建空库 `mychat`；安全组尽量**不对公网开 5432** |
| 博客 nginx | **卸掉**让出 80；本项目用 Compose 内 nginx |
| 数据目录 | `/data/my-chat/`（workspace、ingest、jenkins_home、repo、`.env`） |
| 安全组 | 放行 **22、80**；**不要**对公网开 5432 / 8100 / 8080 / 8888 / 8889 |
| 构建 | 用官方 `maven:*-eclipse-temurin-25`（勿在 CentOS7 容器里走 `mvnw` 自解压）；`DOCKER_BUILDKIT=0` |
| Jenkins | 挂载 `docker.sock` + 宿主机 `/usr/bin/docker` + `cli-plugins`；Health 检查 `http://nginx/` |
| 运维 UI | `--profile ops`：Dozzle `127.0.0.1:8888`、Adminer `127.0.0.1:8889`（SSH 隧道） |
| 发布 | 推 GitHub → Jenkins **Build Now** |
| MCP | `APP_MCP_ENABLED=false` |

CentOS 7 已 EOL：宿主机不要装 JDK 25 / Node。

## 2. 首次安装全流程（一条龙）

每条单独执行；已是 `root` 可去掉 `sudo`。

```bash
# Swap 确认（应有约 2G）
free -h

# 国内拉 Docker Hub 易超时：写镜像加速（换成你自己的阿里云加速器地址；JSON 勿含不可见字符）
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://你的ID.mirror.aliyuncs.com",
    "https://docker.m.daocloud.io"
  ]
}
EOF
python -m json.tool /etc/docker/daemon.json
systemctl reset-failed docker
systemctl restart docker
docker start pg

# 卸掉占 80 的旧博客 nginx（/data/nginx 可留档）
docker stop nginx && docker rm nginx

# 确认 pg；建空库 mychat（已存在则跳过）
docker exec pg pg_isready -U postgres
docker exec -i pg psql -U postgres -d postgres -c "CREATE DATABASE mychat;"

# 目录 + 代码（无 git 时先：yum install -y git）
mkdir -p /data/my-chat/{workspace,ingest,jenkins_home,repo}
git clone https://github.com/All1217/My-Chat.git /data/my-chat/repo

# 密钥只写在服务器文件（勿写进 Git 里的 .env.example）
# 真实 KEY 仅存在 /data/my-chat/.env；Jenkins 每次用 --env-file 读它，不入库
cp /data/my-chat/repo/deploy/.env.example /data/my-chat/.env
chmod 600 /data/my-chat/.env
vi /data/my-chat/.env   # 在这里填真实 PGSQL_PASS / OPENAI_API_KEY 等

cd /data/my-chat/repo
export ENV_FILE=/data/my-chat/.env
export DOCKER_BUILDKIT=0

# 预拉基础镜像（可选，失败则检查加速器）
docker pull maven:3.9.11-eclipse-temurin-25
docker pull eclipse-temurin:25-jre
docker pull node:20-alpine
docker pull nginx:1.26-alpine

# 2C4G 务必串行 build；首次 Maven 下载可能 10～30 分钟，属正常
docker compose -f deploy/docker-compose.yml --env-file "$ENV_FILE" build app
docker compose -f deploy/docker-compose.yml --env-file "$ENV_FILE" build nginx
docker compose -f deploy/docker-compose.yml --env-file "$ENV_FILE" up -d app nginx

# 本机浏览器打开 http://<公网IP>/ ；服务器：
curl -sI http://127.0.0.1/ | head -5
docker logs my-chat-app-1 --tail 50

# 启动 Jenkins（首次会要初始密码）
docker compose -f deploy/docker-compose.yml --env-file "$ENV_FILE" --profile jenkins up -d jenkins
docker exec $(docker ps -qf name=jenkins) docker version
docker exec $(docker ps -qf name=jenkins) cat /var/jenkins_home/secrets/initialAdminPassword
```

**本机打开 Jenkins**：见第 4 节。Jenkins URL 保持 `http://127.0.0.1:8080/`。

**建 Pipeline 任务**：新建 Item → 流水线 → Definition 选 **Pipeline script from SCM** → Git 仓库 URL → 分支 `*/main` → Script Path：`deploy/Jenkinsfile` → 保存 → **Build Now**。

## 3. 日常发布全流程

```bash
# 本机
git push origin main

# 打开 Jenkins（先建隧道，见下）→ 打开 my-chat 任务 → Build Now
# 流水线：checkout 到 /data/my-chat/repo → build app/nginx → up -d → curl http://nginx/

# 服务器抽查
docker ps --filter name=my-chat
curl -sI http://127.0.0.1/ | head -5
```

一般不必在服务器手动 `git pull`（Jenkins 会 checkout）。若只改了未推送的服务器本地文件，下次 Build 可能被远程覆盖。

## 3.1 以后改 API Key / 数据库密码

真实密钥**只**放在服务器 `/data/my-chat/.env`（`chmod 600`），**不要**写入 Git 中的 `deploy/.env.example` 或任何会 `git push` 的文件。Jenkins 每次构建用 `--env-file /data/my-chat/.env`，**不会**用仓库里的 example 覆盖该文件。频次通常很低（泄露轮换 / 厂商换钥）。

密钥分两类，**不要只改 `.env` 就以为聊天 key 已生效**：

| 变量 | 生效位置 | 改完还要做什么 |
|------|----------|----------------|
| `OPENAI_API_KEY` | 启动时若 `llm_model` **为空**才种子写入库；之后聊天读 **`llm_model.api_key`** | `.env` + **改库**（或网站「模型设置」）+ recreate app |
| `EMBEDDING_MODEL_API_KEY`、`EXA_API_KEY`、`BOCHA_API_KEY`、`TAVILY_API_KEY`、`SMITHERY_API_KEY`、`PGSQL_PASS` 等 | 仅容器环境变量 / YAML | `.env` + **`--force-recreate app`**（不必改 `llm_model`） |

```bash
# 1. 改服务器密钥文件
vi /data/my-chat/.env
chmod 600 /data/my-chat/.env

# 2. 若改了 OPENAI_API_KEY：同步库里默认模型（或用网站设置页改 API Key，二选一）
NEW_KEY="$(grep -E '^OPENAI_API_KEY=' /data/my-chat/.env | cut -d= -f2-)"
docker exec -i pg psql -U postgres -d mychat -c \
  "UPDATE llm_model SET api_key = '${NEW_KEY}', updated_at = NOW() WHERE is_default = true;"
# 核对后缀应与 .env 一致
docker exec -i pg psql -U postgres -d mychat -c \
  "SELECT name, right(api_key,4) AS key_suffix FROM llm_model WHERE is_default;"

# 3. 让 app 重新读入环境变量（只改文件不 recreate，容器内仍是旧 env）
cd /data/my-chat/repo
export ENV_FILE=/data/my-chat/.env
docker compose -f deploy/docker-compose.yml --env-file "$ENV_FILE" up -d --force-recreate app
```

只改 embedding / Exa 等：跳过步骤 2，做 1 + 3 即可。也可用 Jenkins **Build Now**（读同一 `.env`）；若当时只改密钥、未推代码，**直接 recreate 比整次 Build 更快**。若 Key 曾误提交到 GitHub，须先在对应云厂商控制台**作废并换新**，再写入服务器 `.env`（并按上表同步 `llm_model`）。

## 4. 运维访问：Jenkins / 日志 / 查库（不对公网开放）

### 4.1 SSH 隧道（推荐一次转三个口）

| 本机地址 | 用途 |
|----------|------|
| `http://127.0.0.1:8080/` | Jenkins 发布 |
| `http://127.0.0.1:8888/` | Dozzle 容器日志 |
| `http://127.0.0.1:8889/` | Adminer 数据库 |

```bash
# Windows PowerShell / CMD / Git Bash
ssh -L 8080:127.0.0.1:8080 -L 8888:127.0.0.1:8888 -L 8889:127.0.0.1:8889 root@<公网IP>
```

窗口保持登录。首次 SSH 的主机指纹只用于确认服务器身份，不是登录密码。

本机 `~/.ssh/config` 示例（以后 `ssh mychat-ops` 即可）：

```sshconfig
Host mychat-ops
  HostName <公网IP>
  User root
  LocalForward 8080 127.0.0.1:8080
  LocalForward 8888 127.0.0.1:8888
  LocalForward 8889 127.0.0.1:8889
```

后台隧道：`ssh -fN mychat-ops`。配公钥可免密。

配了公钥后直接在本机输入`ssh -fN mychat-ops`，然后让窗口挂机即可。

**不推荐**：安全组对公网放行 8080 / 8888 / 8889。

### 4.2 启动 Dozzle + Adminer（首次需 pull）

当前镜像列表若还没有它们，执行下面会自动拉取：

```bash
cd /data/my-chat/repo
export ENV_FILE=/data/my-chat/.env
# 只拉 ops 镜像；勿对整个 profile 执行 pull（会误拉本地构建的 app/nginx 并超时）
docker compose -f deploy/docker-compose.yml --env-file "$ENV_FILE" pull dozzle adminer
docker compose -f deploy/docker-compose.yml --env-file "$ENV_FILE" --profile ops up -d
docker ps --filter name=dozzle --filter name=adminer
```

不用时：`docker compose -f deploy/docker-compose.yml --env-file "$ENV_FILE" --profile ops stop`

### 4.3 Adminer 登录（相对旧笔记的改法）

勿再用公网 `:8080`、`--link pg`、库名 `postgres`（会与 Jenkins 冲突且不安全）。

| 项 | 填写 |
|----|------|
| 系统 | PostgreSQL |
| 服务器 | `host.docker.internal` |
| 用户名 | `postgres` |
| 密码 | `/data/my-chat/.env` 中的 `PGSQL_PASS` |
| 数据库 | **`mychat`**（本项目库，不是 `postgres`） |

- **看结构 / DDL**：点表 →「结构」；或「导出」勾选结构得到 `CREATE TABLE` SQL。  
- **导出数据**：库/表 →「导出」，可选 SQL / CSV / TSV。

无 Web 时：`docker logs -f my-chat-app-1`；`docker exec -it pg psql -U postgres -d mychat`。

## 5. 公网 80 与多项目

当前 `http://<公网IP>/` 直接打开本项目，是因为 Compose 里的 **nginx 容器映射了宿主机 `80:80`**，并把 `/` 指到前端静态资源、`/rag/` 反代到 Java。是的，**nginx 在起作用**，且现阶段 **整站根路径由 My-Chat 独占**。

以后同机再挂其他项目，常见两种做法（需改架构，本仓库样例仍是「独占 80」）：

1. **按域名拆**（推荐）：一个入口 nginx（或现有 web 容器改配置）用 `server_name` 区分 `chat.example.com` / `blog.example.com`，反代到不同容器。
2. **按路径拆**：入口 nginx 配 `location /chat/`、`location /other/`；注意前端若用绝对路径 `/rag`、路由 history 模式，子路径要改 `base` 与反代规则，比按域名麻烦。

不要再起第二个容器抢宿主机 80；应保留**一个**入口反代，后面挂多个 upstream。

## 6. 内存与排障（含实战踩坑）

| 现象 | 处理 |
|------|------|
| 拉镜像 `i/o timeout` | 配 `registry-mirrors`；`daemon.json` 非法会导致 docker 起不来，用 `python -m json.tool` 校验 |
| `mvnw` / tar `Function not implemented` | CentOS7 上勿用 wrapper 自解压；用 `Dockerfile.app` 里的官方 maven 镜像；`DOCKER_BUILDKIT=0` |
| 构建 Exit 137 | Swap；串行 build；已设堆限制 |
| `git: command not found` | `yum install -y git` |
| Jenkins `docker: not found` | compose 挂载宿主机 docker CLI + cli-plugins 后 `--force-recreate jenkins` |
| Health 失败但网站能开 | Jenkins 内应 `curl http://nginx/`，不要 `127.0.0.1` |
| `COMPOSE_BIN=docker compose` 报 compose not found | 勿把带空格的赋值 source 进 sh；Jenkinsfile 已直接写 `docker compose` |
| Adminer 连不上库 | 服务器填 `host.docker.internal`；库名 `mychat`；端口用隧道 `8889` 勿占公网 8080 |
| app 连不上库 | `pg` Up；`.env` 密码正确；URL 为 `host.docker.internal:5432/mychat` |
| 聊天 401 / key 后缀与 `.env` 不一致 | 见 §3.1：改 `OPENAI_API_KEY` 后须同步 `llm_model.api_key` 并 `--force-recreate app` |
| 80 被占 | `docker ps` / `ss -lntp \| grep :80` |

## 7. 环境变量清单

| 变量 | 必需 | 说明 |
|------|------|------|
| `PGSQL_PASS` | 是 | 宿主机 `pg` 密码 |
| `SPRING_DATASOURCE_URL` | 是 | 默认 `jdbc:postgresql://host.docker.internal:5432/mychat?currentSchema=public` |
| `SPRING_DATASOURCE_USERNAME` | 否 | 默认 `postgres` |
| `OPENAI_API_KEY` | 是 | 对话 |
| `EMBEDDING_MODEL_API_KEY` | 是 | 向量 |
| `APP_MCP_ENABLED` | 建议 `false` | 云上关 MCP（Smithery 等）；与 Flyway/表结构无关，见正文说明 |
| `FLYWAY_BASELINE_ON_MIGRATE` | 默认 `false` | 空库保持 false |
| `MYCHAT_DATA` / `MYCHAT_REPO` | 否 | 默认 `/data/my-chat`、`/data/my-chat/repo` |

模板：[`deploy/.env.example`](../deploy/.env.example)。

**`APP_MCP_ENABLED=false`（云上建议保持）**：只关闭远程 MCP 客户端（如 Smithery），减轻 2C4G 负载与外网依赖；**不影响**主聊天、知识库、Flyway。本机因「另一台电脑库表未同步」报错，属于多机库未对齐（见 [`Flyway多机数据库对齐指引.md`](./Flyway多机数据库对齐指引.md)），与该开关无关。云端是**独立** `pg` + 每次发版启动时 Flyway 按镜像内脚本升级**本库**，不会出现「没同步另一台电脑库」这种跨机拷贝问题；正常推代码含新 `V*.sql` 再 Build 即可。
