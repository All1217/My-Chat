### 修复总结

**根因**：`WorkspaceContext` 的 `ThreadLocal` 在 Tomcat 虚拟线程上设置，但在 Netty reactor 线程上读取 — 两个线程不共享 ThreadLocal，`get()` 返回 null，`WorkspaceUtil.resolveSafe()` 回退到默认目录。

**修复**（2 个新文件 + 1 处依赖）：

| 文件                                   | 操作     | 作用                                                         |
| -------------------------------------- | -------- | ------------------------------------------------------------ |
| `pom.xml`                              | 新增依赖 | `io.micrometer:context-propagation`                          |
| `WorkspaceContext.java`                | 重写     | 内嵌 `ThreadLocalAccessor` 实现，注册到 `ContextRegistry`    |
| `ContextPropagationConfiguration.java` | **新建** | `@PostConstruct` 时调用 `Hooks.enableAutomaticContextPropagation()` |

**原理**：

```
Controller (Tomcat 虚拟线程)
  → WorkspaceContext.set("/custom/path")
  → toolChatClient.prompt()...stream()   ← Reactor 自动快照 ThreadLocal
    → [Netty 线程] Reactor 自动恢复 ThreadLocal
      → ShellTool → resolveSafe() → WorkspaceContext.get() → "/custom/path" ✓
    → doFinally → WorkspaceContext.clear()
```
