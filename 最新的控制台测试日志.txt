# 1 什么是面向对象？谈谈你对面向对象的理解[3]

面向过程将过程拆解为一个个顺序执行的步骤，相比于面向过程，面向对象则将这个过程的参与者剥离抽象出来，形成对象，更关注每个参与者在整个过程干什么，提高了复用性、扩展性。

面向对象有三大特性：

1. **封装**：将具体执行细节包装成一个整体，对外仅暴露接口，外部调用者只需知道如何发起这个过程，不必关注具体的执行细节。
2. **继承**：将众多对象共有的一些特性抽象整合成一个新的父类对象，原先的对象作为子对象共同继承这些通用特性，**提高了复用性**。
3. **多态**：父类的**同一个方法**在不同的子类有各自不同的实现，**提高扩展性**。

# 2 JDK、JRE、JVM的区别与联系[3]

![](../../../normal/八股/images/JDK、JRE、JVM的区别与联系.png)

JDK：Java Development Kit，Java开发工具。
JRE：Java Runtime Environment，Java运行时环境。
JVM：Java Virtual Machine，Java运行机器。

先总述三者关系，JDK包含JRE，JRE包含JVM。

JDK是Java开发工具，包含JRE和Java工具（如javac编译器，jconsole性能检测与管理工具），JRE是Java运行时环境，包含lib文件目录和bin目录，其中lib目录存放类库，bin目录实际上就是JVM。我们平常的代码写在后缀为.java的文件里，.java文件经过javac编译形成.class文件，.class文件可以直接被JVM识别运行。
JVM是Java运行机器，可以适配多种不同的操作系统，对应用层程序员隐藏了系统调用和计算机硬件细节，所以Java可以实现只写一套代码然后跨平台部署。

## 2.1 扩展

- javac 是 JDK 提供的核心编译工具，它负责将人类可读的 Java 源代码编译成平台无关的字节码文件。这些字节码可以在任何安装了 JVM 的平台上运行，这是 Java “一次编写，到处运行” 特性的技术基石。同时，javac在编译过程中会进行严格的语法检查、类型校验和注解处理，确保代码质量，为后续的打包和部署提供标准化的中间产物。
- .class文件是平台无关的字节码，是种中间代码，可被JVM直接解释/即时编译运行。

## 25.2 引用数据类型

引用类型存储的是对象在堆（Heap）内存中的地址，而不是实际数据。所有非基本数据类型的对象均属于引用类型，包括：

1. 类对象（如 String、自定义类）
2. 接口
3. 数组
4. 枚举

**示例**：

```
String str = ``"Hello"``; ``// String 是引用类型 ``int``[] arr = {``1``, ``2``, ``3``}; ``// 数组是引用类型 ``Person p = ``new` `Person();``// 自定义类的对象
```

**特点**：

1. 默认值为 null（未指向任何对象）。
2. 传递时是**引用传递**（传递内存地址的副本，共享同一对象）。
3. 内存分配在堆中，由垃圾回收器（GC）管理，可能引发内存泄漏或性能问题。
4. 支持面向对象特性（如继承、多态）。

## 25.3 核心区别

| **特性**     | **基本数据类型**       | **引用类型**             |
| :----------- | :--------------------- | :----------------------- |
| **存储内容** | 直接存储值             | 存储对象的内存地址       |
| **内存位置** | 栈                     | 栈存引用，对象在堆       |
| **默认值**   | 有（如 0、false 等）   | null                     |
| **赋值方式** | 直接复制值             | 复制引用（共享同一对象） |
| **性能**     | 高效（无额外内存开销） | 较低（涉及堆分配和GC）   |
| **用途**     | 简单数据存储           | 复杂对象、面向对象编程   |

**Belady异常**：当为进程分配的物理块数增大时，缺页次数不减反增的异常现象。只有FIFO算法会产生Belady异常。另外，FIFO算法虽然实现简单，但是该算法与进程实际运行时的规律不适应，因为先进入的页面也有可能最经常被访问。因此，算法性能差。

**最近最久未使用置换算法(LRU，least recently used)**：每次淘汰的页面是最近最久未使用的页面。在每个页对应的页表项中，用访问字段记录该页面自上次被访问以来所经历的时间t。当需要淘汰一个页面时，选择现有页面中t值最大的，即最近最久未使用的页面。

最佳置换算法性能最好，但无法实现；先进先出置换算法实现简单，但算法性能差;最近最久未使用置换算法性能好，是最接近OPT算法性能的，但是实现起来需要专门的硬件支持，算法开销大。

**时钟置换算法**是一种**性能和开销较均衡**的算法，又称CLOCK算法，或最近未用算法NRU，NotRecently Used )

- **简单的**CLOCK算法实现方法：再将进程中的页面都通过链接指针链接成一个循环队列，每个页面设置一个访问位，初始为0，当某页被访问时，其访问位置为1。需要淘汰页面时，指针会沿着队列前进，检查页的访问位。如果是0，说明最近一段时间这个页面没被访问过，可能这个页面访问频率比较低，就选择该页换出；如果是1，则将它置为0，暂不换出，继续检查下一个页面。若第一轮扫描中所有页面都是1，则将这些页面的访问位依次置为0后，再进行第二轮扫描(第二轮扫描中一定会有访问位为0的页面，因此简单的CLOCK算法选择一个淘汰页面最多会经过两轮扫描)
- **改进型**CLOCK算法：![](Assets/改进型CLOCK算法.png)总体和简单型一样，但是在页表项除了访问位还增加了修改位，用来标识这个页面数据有没有被修改过。淘汰页面时，不同种类的页面被淘汰的优先级从高到低为：既没有访问过也没用修改过、没有访问过但被修改过、被访问过但没修改过、既被访问过也被修改过。算法淘汰页面可能会经过最多四轮扫描，如图。

### 追问：

**为什么不能是两次握手？**

考虑以下情况：A向B发送连接请求，这个请求中途超时。于是A再次向B发送请求，这一次完整地完成了数据传输并释放连接。这时先前超时的第一次请求到达了B，如果用二次握手，B返回了同意请求，然后一直等待A传数据，浪费资源。如果是三次握手，B在长时间没有收到第三次握手时会自动释放连接。

# 4 HTTP连接类型

HTTP连接类型主要分为**非持久性连接**和**持久性连接**，它们在数据传输效率和资源利用上有显著差异。

**非持久性连接**是HTTP/1.0的默认连接方式。每个TCP连接只能传输一个对象，传输完成后立即关闭连接。例如，当一个网页包含多个资源（如HTML文件和图片）时，客户端需要为每个资源单独建立TCP连接。这种方式的缺点包括每个对象需要额外的两个RTT（往返时间）来建立连接，以及操作系统需要为每个连接分配资源，增加了服务器的负担。

**持久性连接**是HTTP/1.1的默认连接方式。一个TCP连接可以传输多个对象，服务器在发送响应后保持连接打开，后续请求可以复用该连接。持久性连接分为两种模式：**无流水线模式**和**流水线模式**。无流水线模式下，客户端在收到前一个响应后才发送下一个请求，而流水线模式允许客户端同时发送多个请求，服务器也可以并行响应，从而显著减少延迟。

**非持久性连接的缺点**包括响应时间长、资源开销大以及每个连接都需要经历TCP慢启动阶段。而持久性连接通过减少TCP连接的数量和复用连接，优化了传输效率，尤其是在流水线模式下，所有引用对象只需一个RTT即可完成传输。

总结来说，持久性连接在性能和资源利用上优于非持久性连接，是现代HTTP通信的主流选择。

- **定义**：把调入内存的页面根据调入的先后顺序排成一个队列，需要换出页面时选择队头页面即可。
- **特点**：

## 页面置换算法

**背景**：在请求分页存储管理中，当内存空间不够时，需要将内存中暂时用不到的信息换出到外存，此时需要选择合适的页面置换算法来决定换出哪个页面。

---

### 1. 最佳置换算法（OPT）
- **特点**：性能最好，但**无法实现**，属于理论算法，主要用于验证和测试其他算法的性能。

---

### 2. 先进先出置换算法（FIFO）
- **定义**：把调入内存的页面根据调入的先后顺序排成一个队列，需要换出页面时选择队头页面即可。
- **特点**：
  - 实现简单。
  - 只有FIFO算法会产生**Belady异常**（当为进程分配的物理块数增大时，缺页次数不减反增的异常现象）。
  - 算法与进程实际运行规律不适应，因为先进入的页面也有可能最经常被访问，因此**算法性能差**。

---

### 3. 最近最久未使用置换算法（LRU）
- **定义**：每次淘汰的页面是最近最久未使用的页面。
- **实现方式**：在每个页对应的页表项中，用访问字段记录该页面自上次被访问以来所经历的时间t，淘汰时选择t值最大的页面。
- **特点**：
  - **性能好，是最接近OPT算法性能的**。
  - 实现起来需要专门的硬件支持，**算法开销大**。

---

### 4. 时钟置换算法（CLOCK / NRU）
- **定位**：一种**性能和开销较均衡**的算法，又称最近未用算法（NRU）。

#### 简单型CLOCK算法
- **实现方法**：将进程中的页面通过链接指针链接成一个循环队列，每个页面设置一个访问位（初始为0），当某页被访问时，访问位置为1。
- **淘汰过程**：指针沿队列前进，检查访问位：若为0则换出该页；若为1则置为0并继续检查。若第一轮扫描所有页面都是1，则全部置为0后进行第二轮扫描（第二轮必有访问位为0的页面）。因此选择一个淘汰页面**最多经过两轮扫描**。

#### 改进型CLOCK算法
- **改进点**：在页表项中增加**修改位**，用于标识页面数据是否被修改过。
- **淘汰优先级**（从高到低）：
  1. 既没访问过也没修改过
  2. 没访问过但被修改过
  3. 被访问过但没修改过
  4. 既被访问过也被修改过
- **开销**：淘汰页面可能经过**最多四轮扫描**。
